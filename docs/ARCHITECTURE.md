# 架构

## 一句话

一个 Rust 外壳负责 Windows 窗口行为，一个 React 前端负责平台 UI 与组件运行时，第三方组件在沙箱 iframe 里运行，只能通过一条带权限校验的 RPC 桥跟平台说话。

## 零内置原则

**平台本身不提供任何组件。** 装好、第一次打开，桌面上什么都没有 —— 就像刚装好的 VS Code 没有插件。

这条不是口号，它约束三件事：

1. **核心与内容是分开的。** 核心只有：画布、窗口层、组件宿主、权限系统、安装/卸载、组件库、设置。凡是"桌面上能看见的东西"，都是组件包。
2. **官方组件没有特权。** 随应用分发的组件包（`public/widgets`）走的是和第三方完全相同的 manifest、沙箱、权限桥。它们只是"已经在你硬盘上"，不是"被编译进内核"。这也是唯一能保证第三方 API 够用的办法 —— 官方组件是第一用户。
3. **"没装任何组件"必须是一个体面的状态。** 空画布不能是错误页，组件库不能是死胡同。零组件时整个平台应该能退化成托盘图标 + 后台进程，不常驻任何 WebView。

### 安装 ≠ 发现

注册表（`runtime/registry.ts`）返回的是**发现到的**包，包含两类来源：

| 来源 | 位置 | 是否算已安装 |
|---|---|---|
| `bundled` | 应用资源里的 `widgets/` | **否**，必须显式安装（`installedIds`） |
| `user` | `%APPDATA%/<identifier>/widgets` | **是**，在磁盘上就是装了 |

这个区分是产品定义的一部分。如果内置包自动算已安装，平台就退化成一个"内置了几个组件的桌面工具"，扩展体系变成装饰。

### 安装是复制，不是记账

v0.1 的"安装内置包"只在 `installedIds` 里记个 id，文件仍留在应用资源里。v0.2 改成 VS Code 处理内置扩展的做法：**把包目录复制进用户扩展目录再注册**（`install_widget` 先删旧目录再递归拷贝），这样安装 / 卸载 / 覆盖升级对官方包和第三方包完全同构，只有一条代码路径。

### 已知缺口

| 缺口 | 影响 |
| --- | --- |
| 撤销授权不同步到已打开的窗口 | 宿主页的 `granted` 在 `boot()` 时固定，要重开窗口才生效 |
| 没有每实例配置 | 组件想加"字号 / 显示日期"只能自己画设置 UI、自己存 |
| 加载失败没有兜底页 | 白屏，分不清 404 和组件自己的 JS 崩了 |

三条都在 ROADMAP v0.3。

## 三层

```
┌─────────────────────────────────────────────────────┐
│  平台外壳（React，主窗口）                            │
│  组件库 · 画布 · 属性面板 · 平台状态（Zustand）        │
├─────────────────────────────────────────────────────┤
│  组件运行时（runtime/）                               │
│  manifest 校验 · 注册表 · RPC 桥 + 权限闸门            │
├─────────────────────────────────────────────────────┤
│  沙箱组件（iframe，opaque origin）                     │
│  第三方 HTML/CSS/JS，只能 postMessage                  │
└─────────────────────────────────────────────────────┘
        ↕ Tauri 命令                  ↕ Win32
┌─────────────────────────────────────────────────────┐
│  Rust 侧                                             │
│  widgets.rs：组件包扫描 / 安装 / 卸载                  │
│  protocol.rs：lattice-widget 协议（用户组件的静态文件） │
│  runner.rs：Placement → 窗口的增量同步、宿主页配置     │
│  desktop.rs：层级、穿透、焦点、圆角、底层守卫（Win32） │
│  state.rs / widget_store.rs：状态与组件数据落盘        │
└─────────────────────────────────────────────────────┘
```

Rust 只做"窗口与文件"，不碰 UI。判断标准很简单：**需要 Win32 句柄或磁盘路径的，才下到 Rust**；其余（布局、主题、权限 UI）都在前端，改起来不用重编译。

## 两个状态：设计态与运行态

这是最容易混淆的地方，先定清楚：

| | 设计态 | 运行态 |
| --- | --- | --- |
| 宿主 | 主窗口里的一块画布 | 每个组件一个独立 WebviewWindow |
| 用途 | 摆位置、调尺寸、配层级、授权限 | 真正贴在桌面上常驻 |
| 组件渲染 | `WidgetFrame.tsx` 里的 iframe | 宿主页 `widget-host.html` 里再套一层 iframe |
| 生命周期 | 跟着主窗口 | 跟着平台进程 |

**两个宿主，一套桥。** 设计态和运行态的 iframe 都走 `runtime/bridge.ts` 的同一张方法表、同一套权限校验，所以不会出现"预览能用、桌面上不能用"的分叉——这也是加新能力时唯一需要守住的对称性。

v0.1 先把**运行时协议、权限模型、组件包格式**这三件事定死，因为它们改起来最贵。窗口形态换掉时（iframe → 独立窗口）这三样一行没动，这就是当初先做协议的价值。

## 组件沙箱

`<iframe sandbox="allow-scripts allow-forms">` —— 关键在**没有** `allow-same-origin`。

这带来一个不透明源（opaque origin），于是：

- 读不到父窗口 DOM、`window.parent` 上的任何属性
- `localStorage` 直接抛 `SecurityError`
- `fetch` 发出去带 `Origin: null`，跨源请求会被拦
- Cookie、IndexedDB 全部不可用

结论：组件**什么都干不了，除非走桥**。这就是整个安全模型的地基。

`allow-forms` 是后来补的，理由不是"想开"，而是"不开就坏"：沙箱里少了这一位，浏览器会把表单提交整条拦掉，`submit` 事件不触发、不报错，`<form>` + 回车这种最普通的写法静默失效。它不扩大上面的任何一条 —— 表单只能提交到组件自己的不透明源，真要外发请求，`fetch` 早就够了。

### 桥的鉴权

```ts
window.addEventListener("message", (event) => {
  if (event.source !== iframeRef.current.contentWindow) return;  // ① 来源校验
  if (!isBridgeRequest(event.data)) return;
  handleBridgeRequest(event.data, { granted });                   // ② 权限校验
});
```

① 用**窗口引用比对**而不是 `event.origin`。因为沙箱 iframe 的 origin 是字符串 `"null"`，所有组件都长一样，靠 origin 分不出实例，也就无法阻止 A 组件冒充 B 组件。

② 权限按 `widgetId` 授予（不是按实例）。语义是"你信不信任这段代码"，跟桌面上摆了几份无关。

未授权时返回结构化错误 `{ ok: false, code: "permission_denied" }`，不是抛异常 —— 组件需要自己降级（比如不显示剪贴板按钮），而不是整个崩掉。

## 组件包

组件是**目录**，不是构建产物：

```
lattice.clock/
  manifest.json    清单（契约）
  index.html       入口
  icon.svg         图标（可选，清单的 icon 指过来）
  widget.js        逻辑
  style.css        样式
```

不需要打包、不需要构建步骤。这是刻意的：扩展平台的门槛必须低到"会写 HTML 就能写组件"。等 SDK 成熟后再引入可选的构建流程。

内置组件放 `public/widgets/`，随前端资源打包；用户安装的组件放 `%APPDATA%\com.iron-tom.lattice\widgets\`。

### 分发：目录是文件，信任在包上

平台没有服务端。所以"商店"不是一套后端，而是三样东西：

1. **一份静态 `registry.json`**（schema 1）—— 每个组件一行：id、名字、版本、包地址、包的 sha256、签名、发布者公钥。内置的那份跟着应用发（`public/store/`），也可以在设置里换成任何静态地址。
2. **一批签名过的 `.lattice` 包** —— 签名是 ed25519，签的是**整个包文件的字节**。包本身是确定性 zip，所以"这份签名对应的是不是这个文件"是个能回答的问题。
3. **本地钉住的发布者钥匙** —— `state.json` 里的 `trustedKeys`，第一次安装时写入（TOFU）。

装的时候三道校验，顺序不能换：摘要 → 签名 → 钉住的钥匙。**目录不签名**，因为它只是索引；改目录最多能让某个条目指向别的包（第一/二道挂）或换一把钥匙（第三道挂，且界面会印出两把指纹要用户点头）。

取舍的完整论证在 [ROADMAP 的 v0.5 四个取舍](./ROADMAP.md#v05-的四个取舍)，作者视角的流程在 [WIDGET_SPEC §9](./WIDGET_SPEC.md#9-发布版本与签名)。

## 数据

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 组件摆放、层级、授权、主题、网格吸附、本机档案、桌面矩形、目录地址、钉住的钥匙、评分 | `%APPDATA%\com.iron-tom.lattice\state.json` | Zustand persist 的自定义 `StateStorage` → `state_write` |
| 组件私有数据 | `%APPDATA%\com.iron-tom.lattice\widget-data\<widgetId>.json` | 由宿主代存，组件自己碰不到 localStorage |
| 用户安装的组件 | `%APPDATA%\com.iron-tom.lattice\widgets\<id>\` | Rust 管理，经 `lattice-widget` 协议加载 |
| 上一代组件（回滚用） | `%APPDATA%\com.iron-tom.lattice\widget-backups\<id>\` | 覆盖安装前整份复制，只留一代，回滚是交换 |
| 举报与评分 | `%APPDATA%\com.iron-tom.lattice\reports\<id>-<unix>.json` | 写成文件，不上传 —— 没有服务端就没有"提交" |
| 下载过的包 | `%APPDATA%\com.iron-tom.lattice\store-cache\<sha256>.lattice` | 按摘要命名，天然的复用与去重 |

**不用 `localStorage`**，原因见 ROADMAP「被推翻的决定」第 2 条：这台机器的 WebView2 把它整个放在内存里，进程一退就没了。文件写入走"临时文件 + 原子替换"，写到一半断电也不会留下半截 JSON。

组件数据放宿主而不是组件里，有三个好处：将来换后端（SQLite）组件不用改；组件之间互相看不到数据；同一组件的多个实例能通过广播收敛成同一份视图。

## 窗口行为（Win32）

窗口属性按"这个组件要不要打字"分流，由清单的 `interactive` 决定，不按组件名硬编码：

| 需求 | 纯展示（`interactive: false`） | 可输入（`interactive: true`，默认） |
| --- | --- | --- |
| 抢不抢焦点 | `WS_EX_NOACTIVATE`，点了不打断你 | 不设，能拿键盘焦点 |
| 进不进 Alt+Tab | `WS_EX_TOOLWINDOW` 排除 | 同样排除 |
| 鼠标穿透 | `WS_EX_LAYERED \| WS_EX_TRANSPARENT`（按实例开关） | 同左 |
| 挂哪 | WorkerW（拿不到降级 `HWND_BOTTOM`） | 不挂 WorkerW，压 `HWND_BOTTOM` |
| z 序守卫 | 不需要 | 子类化拦 `WM_WINDOWPOSCHANGING`，给"往上提"补 `SWP_NOZORDER` |

层级有两种：

- `desktop`：`SetParent` 到 WorkerW。向 `Progman` 发 `0x052C` 让它派生 WorkerW，再枚举找到挂着 `SHELLDLL_DefView` 的窗口的兄弟 WorkerW，把组件挂上去。效果是组件沉到桌面图标之上、普通窗口之下。**这是"桌面小组件"体感的关键**。
- `top`：先 `SetParent(null)` 脱离，再 `HWND_TOPMOST`。

拿不到 WorkerW 时降级为 `HWND_BOTTOM`，至少不会浮在最上层挡住内容。

z 序守卫是 v0.2 补的：可激活的窗口被点中时，Windows 会顺手把它提到最前，切走又掉回底层——用户看到的是"闪来闪去"。拦掉"往上提"不影响激活，键盘照样进得来。

## 常驻：谁活着，谁停下

"桌面组件"这个词意味着这个东西要开几周，而不是几分钟。常驻形态有四件事是设计问题，不是功能问题：

**入口不能只有一个。** 主窗口收起来之后（桌面上还有组件时关窗口只是 `hide()`），用户得有个地方能把它要回来。所以有托盘，托盘和设置菜单调**同一组命令**（`show_main` / `toggle_paused` / `app.exit`）——各写一套的话两边状态会飘。

**"暂停"要真的停。** 不是停调度器：组件还在画、还在跑自己的 `requestAnimationFrame`，看不见却在烧 CPU。做法是把窗口 `hide()`，`document.visibilityState` 随之变成 `hidden`，调度器那条"两个来源取与"的链路自动跟着停——一个动作同时解决了"看不见"和"别跑了"。

**崩溃要能自己回来，但不能无限回来。** 一个每次加载都崩的组件，如果每次都重载，就变成一个每秒一次的循环：CPU 打满、日志刷屏、用户不知道是哪个组件。所以按失败类型分流（`render` / `gpu` 才重载，`browser` 直接放弃）+ 一分钟三次的限流 + 放弃之后在界面上留一个 `Try again`。三者缺一：只有分流会无限重载，只有限流会静默消失。

**出网是白名单，不是开关。** 组件是不可信代码，"允许联网"这种粒度对用户没有意义——他没法审阅。所以权限之外还要清单里的主机列表，且不跟随重定向（跟随等于只检查了第一跳）。走 IPC 而不是本地 HTTP 代理：本地端口会留下一条组件能直接 `fetch` 的路。

## 性能预算

常驻应用，预算是硬指标：

| 指标 | 目标 |
| --- | --- |
| 空载内存 | < 80 MB |
| 空载 CPU | ≈ 0% |
| 5 个组件时 CPU | < 2% |

手段：不可见组件暂停渲染、动画走 CSS `transform/opacity`、组件定时器统一由平台调度（v0.3 已落地，见 `runtime/schedule.ts`）、暂停全部时直接把窗口藏起来（`hide()` 顺带把 `document.visibilityState` 翻成 `hidden`，调度器那条链路自动跟着停）。

## 已知取舍

| 决定 | 代价 | 为什么接受 |
| --- | --- | --- |
| 窗口不透明，圆角靠 `SetWindowRgn` 裁 | 做不了异形窗口、投影、模糊背景；圆角外侧像素是死区 | 逐像素透明要求 DirectComposition，这台机器拿不到（见 ROADMAP 第 1 条） |
| 每个组件一个 WebView | 内存随组件数线性涨 | 崩溃隔离、独立 DPI、独立输入焦点都靠它；同一 WebView 装多组件的方案留到性能告急时再评估 |
| 用户组件走自定义协议，不走 `file://` | 多一层协议代码、Windows 上 URL 形式特殊 | `file://` 没有源隔离，组件能直接读整个磁盘 |
| 内置组件的文档拿不到 CSP 头 | 同一份代码装成内置和装进用户目录，出网行为不一样 | 内置组件走应用自己的前端资源管线，随二进制分发、信任级别和平台本体一样；用户组件的 CSP 在 `csp.rs` 一处生成（见 AGENTS 缺口表） |
| 不引入 Tailwind | 手写 CSS 更长（3 102 行） | 定制工作台用变量层更可控，少一个构建依赖，组件也只认 `--lattice-*` |
| 本机档案不是账号系统 | "登录"只写本地 `state.json` | 没有服务端。文案上明说"只保存在这台电脑"，免得被当成云端账号；真做同步时换 `signIn/signOut` 即可 |
| 商店是一份静态 JSON，不是后端 | 目录要手工重发；评分不汇总；举报要用户自己发给作者 | 没有服务端就别做需要服务端的形状。接后端时换的只是"目录从哪儿取""举报写到哪儿"，`parseCatalogue` / `planInstall` / 验签那一层一行都不用动 |
| 信任靠本地钉住的钥匙（TOFU），没有 PKI | 第一次安装只能信"这次看到的"；换钥匙要用户手动点头 | 真正的 PKI 需要一个平台方来签发和吊销，这个项目没有也不该假装有。界面把指纹印出来，是为了让"换人"这件事有一次被看见的机会 |
| 备份只留一代，回滚做成交换 | 更新两次之后回不到第一版 | "留几代"是个没有正确答案的配置项，而用户真正需要的是"回到刚才那个"。交换让按钮可以按两次、两个方向都成立 |
